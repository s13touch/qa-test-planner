# QA Test Planner

Скилл для AI-агентов (Claude Code, Codex, Cursor и др.), который превращает документацию в готовые артефакты QA: **тест-планы**, **тест-кейсы**, **баг-репорты**, **регрессионные наборы** и **валидацию дизайна по Figma**.

## О проекте

QA Test Planner — это набор инструкций и шаблонов для AI-агента, который помогает QA-инженерам быстро и единообразно создавать документы тестирования. Скилл принимает **любую документацию** (требования, спеки, user stories, API-референсы, дизайн, тикеты) и выдаёт результат в строго заданных форматах.

Цель — убрать рутину по оформлению и держать единый стандарт в команде.

## Возможности

| Возможность | Что выдаёт |
|-------------|-----------|
| 🧪 **Тест-кейсы** | Единая таблица `№ требования \| Номер кейса \| Приоритет \| Описание` |
| 📋 **Тест-план** | Резюме, объём, стратегия, окружение, критерии входа/выхода, риски, артефакты |
| 🐞 **Баг-репорты** | Заголовок «что + где + при каких условиях», таблица «Шаги → Фактический → Ожидаемый» |
| 🔁 **Регрессия** | Наборы smoke / targeted / full / sanity, порядок выполнения, критерии Pass/Fail |
| 📊 **Отчёт о прогоне** | Сводка, результаты по приоритетам, падения, риски, матрица покрытия |
| 🎨 **Валидация Figma** | Сравнение реализации с макетом через Figma MCP |

## Установка

**Вариант 1: как skill для Claude Code / агентов**

```bash
# Скопировать папку скилла в каталог навыков
git clone https://github.com/s13touch/qa-test-planner.git
cp -r qa-test-planner/qa-test-planner ~/.claude/skills/
```

**Вариант 2: из архива**

Скачайте `qa-test-planner.zip` из релизов и распакуйте в каталог навыков.

**Вариант 3: через агента**

> Установи скилл QA Test Planner из репозитория https://github.com/s13touch/qa-test-planner.

## Использование

Скилл использует **явный вызов** по имени:

```
/qa-test-planner
qa-test-planner
используй скилл qa-test-planner
```

Примеры запросов:

```
Составь тест-план для функции авторизации
Сгенерируй тест-кейсы по документации в папке docs/
Создай баг-репорт: форма отправляется с пустым email
Собери smoke-набор для модуля оплаты
Сравни страницу входа с макетом Figma по <URL>
```

## Форматы вывода

### Тест-кейсы

*Название раздела*

| № требования | Номер кейса | Приоритет | Описание тест-кейса |
| ------------ | ----------- | --------- | ------------------- |
| 12 | TC-01 | P0 | При нажатии на кнопку «Заключить договор» открывается модальное окно. |
| 12 | TC-02 | P1 | [EP] При выборе типа договора «Стандартный» все поля формы отображаются корректно. |

- Сквозная нумерация `TC-01`, `TC-02`, … по всем разделам.
- Приоритет `P0–P3`.
- Группировка по разделам источника.

### Баг-репорт

```markdown
# BUG-101: Будильник звенит дважды на странице будильников после нажатия «Отложить»

**Серьёзность:** High | **Приоритет:** P1 | **Тип:** Functional | **Статус:** Open

## Шаги и результаты

| Шаги воспроизведения | Фактический результат | Ожидаемый результат |
| --- | --- | --- |
| 1. …<br>2. …<br>3. … | Что происходит на самом деле | Что должно происходить |
```

Полные форматы — в [`qa-test-planner/SKILL.md`](qa-test-planner/SKILL.md).
