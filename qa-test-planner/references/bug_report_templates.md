# Шаблоны баг-репортов

Справочник по оформлению багов. **Единственный формат** — из `SKILL.md` (раздел «Deep Dive: Баг-репортинг»).

---

## Правило заголовка

Заголовок обязан отвечать на три вопроса — **что произошло**, **где произошло** и **при каких условиях** — и при этом быть кратким и лаконичным (одна строка).

Формат: `[Что произошло] + [где] + [при каких условиях]`

- Плохо: `Баг с будильником`
- Хорошо: `Будильник звенит дважды на странице будильников после нажатия «Отложить»`

---

## Базовый шаблон

```markdown
# BUG-[ID]: [Что произошло + где + при каких условиях]

**Серьёзность:** Critical | High | Medium | Low
**Приоритет:** P0 | P1 | P2 | P3
**Тип:** Functional | UI | Performance | Security
**Статус:** Open | In Progress | Fixed | Closed

## Окружение
- **ОС:** [Windows 11, macOS 14 и т.д.]
- **Браузер:** [Chrome 120, Firefox 121 и т.д.]
- **Устройство:** [Десктоп, iPhone 15 и т.д.]
- **Сборка:** [Версия/коммит]
- **URL:** [Страница, где воспроизводится баг]

## Описание
[Понятное краткое описание проблемы]

## Шаги и результаты

| Шаги воспроизведения | Фактический результат | Ожидаемый результат |
| --- | --- | --- |
| 1. [Конкретный шаг]<br>2. [Конкретный шаг]<br>3. [Конкретный шаг] | [Что происходит на самом деле] | [Что должно происходить] |

## Визуальные доказательства
- Скриншот: [приложен]
- Видео: [ссылка, если есть]
- Ошибки консоли: [вставить ошибки]

## Дополнительный контекст
- Связано с: [Фича/тикет]
- Регресс: [Да/Нет]
- Макет Figma: [Ссылка, если UI-баг]
```

---

## Пример

```markdown
# BUG-101: Будильник звенит дважды на странице будильников после нажатия «Отложить»

**Серьёзность:** High
**Приоритет:** P1
**Тип:** Functional
**Статус:** Open

## Окружение
- **ОС:** Windows 11
- **Браузер:** Chrome 120
- **Устройство:** Десктоп
- **Сборка:** v2.0.0
- **URL:** http://localhost:5173/timer/alarms

## Описание
После нажатия «Отложить» (snooze) на одно и то же срабатывание будильника создаются два pending-события, из-за чего одновременно показываются два popup и звучит два звука.

## Шаги и результаты

| Шаги воспроизведения | Фактический результат | Ожидаемый результат |
| --- | --- | --- |
| 1. Создать будильник с repeat_mode=once и snooze_minutes=1<br>2. Дождаться срабатывания и нажать «Отложить»<br>3. Дождаться повторного срабатывания через ~1 минуту | Создаются два pending-события; срабатывают два popup и два звука одновременно | Одно событие: один popup и один звук |

## Визуальные доказательства
- Скриншот: приложен (два popup одновременно)
- Видео: [ссылка]
- Ошибки консоли: отсутствуют

## Дополнительный контекст
- Связано с: domain Alarms, `alarmEventService` (dedup `deliveryInFlight`)
- Регресс: Нет
- Макет Figma: —
```

## Определения серьёзности

| Уровень | Критерии | Время реакции | Примеры |
|-------|----------|---------------|---------|
| **Critical (P0)** | Падение системы, потеря данных, безопасность | < 4 часов | Вход сломан, оплата не проходит, утечка данных |
| **High (P1)** | Крупная фича сломана, нет обходного пути | < 24 часов | Поиск не работает, оформление заказа падает |
| **Medium (P2)** | Фича работает частично, есть обходной путь | < 1 недели | В фильтре нет опции, медленная загрузка |
| **Low (P3)** | Косметика, редкий крайний случай | Следующий релиз | Опечатка, мелкое выравнивание |

---

## Матрица «Приоритет / Серьёзность»

|  | Низкое влияние | Среднее влияние | Высокое влияние | Критичное влияние |
|--|-----------|---------------|-------------|-----------------|
| **Редко** | P3 | P3 | P2 | P1 |
| **Иногда** | P3 | P2 | P1 | P0 |
| **Часто** | P2 | P1 | P0 | P0 |
| **Всегда** | P2 | P1 | P0 | P0 |
