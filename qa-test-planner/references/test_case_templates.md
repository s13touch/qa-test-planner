# Шаблоны тест-кейсов

Справочник по форматам тест-кейсов. **Единственный формат вывода** — таблица, определённая в `SKILL.md` (раздел «Формат вывода — таблица тест-кейсов (ОБЯЗАТЕЛЬНО)»).

---

## Базовый формат

```markdown
*Название раздела*

| № требования | Номер кейса | Приоритет | Описание тест-кейса |
| ------------ | ----------- | --------- | ------------------- |
| 12 | TC-01 | P0 | При нажатии на кнопку "Заключить договор" открывается модальное окно "Заключение договора". |
| 12 | TC-02 | P1 | [EP] При выборе типа договора "Стандартный" все поля формы отображаются корректно. |
```

### Правила

- Одна строка = один тест-кейс.
- **№ требования** — идентификатор из источника; если нумерации нет — ближайшая ссылка (раздел/тистория/тикет) или `—`.
- **Номер кейса** — сквозная нумерация `TC-01`, `TC-02`, … по всем разделам (не перезапускается).
- **Приоритет** — `P0 | P1 | P2 | P3`.
- **Описание тест-кейса** — одно краткое предложение; можно префиксовать тег техники `[EP]` или `[BVA]`.
- Тест-кейсы группируются по разделам источника; название раздела сохраняется.
- Не добавляются лишние колонки, предусловия или заметки.

## Примеры по типам

### Функциональные

```markdown
*Оплата заказа*

| № требования | Номер кейса | Приоритет | Описание тест-кейса |
| ------------ | ----------- | --------- | ------------------- |
| 14 | TC-01 | P0 | При оплате валидной картой заказ создаётся и открывается страница успеха. |
| 14 | TC-02 | P1 | При отклонённой карте отображается ошибка, заказ не создаётся. |
```

### UI / визуальные

```markdown
*Кнопка "Оформить"*

| № требования | Номер кейса | Приоритет | Описание тест-кейса |
| ------------ | ----------- | --------- | ------------------- |
| 21 | TC-03 | P1 | Кнопка "Оформить" соответствует макету Figma по цвету, размеру и скруглению. |
```

### Интеграционные

```markdown
*Интеграция с платёжным шлюзом*

| № требования | Номер кейса | Приоритет | Описание тест-кейса |
| ------------ | ----------- | --------- | ------------------- |
| 33 | TC-04 | P1 | При оплате запрос уходит в платёжный шлюз и возвращает статус 200 с JSON-ответом. |
```

### Регрессионные

```markdown
*Оформление заказа (регресс)*

| № требования | Номер кейса | Приоритет | Описание тест-кейса |
| ------------ | ----------- | --------- | ------------------- |
| — | TC-05 | P1 | После изменений основная логика оформления заказа продолжает работать. |
```

### Производительность

```markdown
*Загрузка каталога*

| № требования | Номер кейса | Приоритет | Описание тест-кейса |
| ------------ | ----------- | --------- | ------------------- |
| 45 | TC-06 | P2 | [BVA] Страница каталога загружается менее чем за 3 секунды. |
```

### Безопасность

```markdown
*Аутентификация*

| № требования | Номер кейса | Приоритет | Описание тест-кейса |
| ------------ | ----------- | --------- | ------------------- |
| 52 | TC-07 | P0 | При попытке SQL-инъекции в поле входа запрос блокируется и данные не раскрываются. |
```

## Типы тестов

| Тип | На что направлен | Пример |
|------|-------|---------|
| Функциональный | Бизнес-логика | Вход с валидными данными |
| UI/Визуальный | Внешний вид, вёрстка | Кнопка совпадает с макетом Figma |
| Интеграционный | Взаимодействие компонентов | API отдаёт данные на фронтенд |
| Регрессионный | Существующий функционал | Прошлые фичи продолжают работать |
| Производительность | Скорость, нагрузка | Страница загружается менее 3 секунд |
| Безопасность | Уязвимости | SQL-инъекция предотвращена |

---

## Определения приоритетов

| Приоритет | Описание | Когда запускать |
|----------|-------------|-------------|
| P0 | Критичный путь, блокирует релиз | Каждую сборку |
| P1 | Крупные фичи, высокое влияние | Ежедневно/еженедельно |
| P2 | Стандартные фичи, среднее влияние | Еженедельно/на релиз |
| P3 | Мелкие фичи, низкое влияние | Только на релиз |
