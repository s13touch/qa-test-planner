# Валидация дизайна по Figma (с MCP)

Руководство по проверке реализации UI против макетов Figma через Figma MCP.

> Форматы вывода определяются в `SKILL.md`:
> - тест-кейсы — раздел «Формат вывода — таблица тест-кейсов (ОБЯЗАТЕЛЬНО)»;
> - баг-репорты — раздел «Deep Dive: Баг-репортинг».
> Здесь — только процесс валидации и чек-листы проверки.

---

## Предусловия

**Обязательно:**
- настроен Figma MCP сервер;
- есть доступ к файлам дизайна Figma;
- есть Figma-ссылки на компоненты/страницы.

**Настройка:**
```bash
# Установить Figma MCP (по официальной документации)
# Настроить API-токен
# Проверить доступ к файлам дизайна
```

## Процесс валидации

### Шаг 1: получить спецификацию из Figma

**Через Figma MCP:**
```
"Получи спецификации основной кнопки из Figma-файла [URL]"

Ответ содержит:
- Размеры (ширина, высота)
- Цвета (фон, текст, граница)
- Типографику (шрифт, размер, начертание)
- Отступы (padding, margin)
- Скругление углов
- Состояния (default, hover, active, disabled)
```

### Шаг 2: сверить реализацию

**DevTools браузера:**
1. Инспектировать элемент.
2. Проверить computed styles.
3. Сверить размеры.
4. Сверить цвета (пипетка).
5. Проверить типографику.
6. Проверить интерактивные состояния.

### Шаг 3: задокументировать расхождения

При расхождении создаётся **тест-кейс** (если нужно покрытие) и/или **баг-репорт** (если есть дефект). Оба — строго в наших форматах из `SKILL.md`.

**Тест-кейс (наш формат):**

```markdown
*Кнопка "Оформить"*

| № требования | Номер кейса | Приоритет | Описание тест-кейса |
| --- | --- | --- | --- |
| 21 | TC-05 | P1 | Кнопка "Оформить" совпадает с макетом Figma по цвету, размеру и скруглению. |
| 21 | TC-06 | P2 | [BVA] Состояние hover кнопки "Оформить" соответствует макету Figma. |
```

**Баг-репорт (наш формат):**


## Типичные расхождения

### Типографика
- Неверное начертание (Regular вместо Medium)
- Неверный размер шрифта
- Отсутствует line-height
- Hex-код цвета отличается на оттенок

### Отступы
- Padding не совпадает
- Непостоянные margin
- Смещение по сетке
- Разные интервалы между компонентами

### Цвета
- Hex отличается (#0066FF против #0052CC)
- Не применена прозрачность
- Неверные углы градиента
- Неверные цвета теней

### Адаптивность
- Breakpoints не совпадают
- Мобильный layout отличается
- Планшетный вид непоследователен
- Масштабирование не как в макете

## Идеи автоматизации

### Визуальное регрессионное тестирование
- Снимать скриншоты.
- Сравнивать с экспортом Figma.
- Подсвечивать пиксельные различия.
- Инструменты: Percy, Chromatic, BackstopJS.

### Валидация design tokens
- Извлекать токены из Figma.
- Сравнивать с CSS-переменными.
- Отмечать несоответствия.
- Автоматизировать скриптами.

## Лучшие практики

**НУЖНО:**
- ✅ Всегда ссылаться на конкретный Figma URL.
- ✅ Проверять все состояния компонента.
- ✅ Проверять адаптивные breakpoints.
- ✅ Фиксировать точные значения (не «примерно похоже»).
- ✅ Делать скриншоты и макета, и реализации.
- ✅ Проверять в нескольких браузерах.

**НЕЛЬЗЯ:**
- ❌ Полагаться на «выглядит нормально».
- ❌ Пропускать hover/active состояния.
- ❌ Игнорировать мелкие отличия цвета.
- ❌ Проверять только на одном размере экрана.
- ❌ Забывать проверять типографику.
- ❌ Упускать проблемы отступов.
